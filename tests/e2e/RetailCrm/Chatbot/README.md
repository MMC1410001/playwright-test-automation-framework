## Authentication Strategy

The app uses mobile OTP login (`9000000001`), which cannot be intercepted by automation.  
The test suite handles this with a **two-step approach**:

```
Step 1 (once)  →  auth.setup.js   — real OTP login → saves session to .auth/retail_crm-auth.json
Step 2 (every run)  →  homepage.spec.js   — loads saved session, skips OTP entirely
```

The dev-server session expires in **~3–4 minutes**. Run the setup script immediately before running tests.  
The script **auto-detects** whether the saved session is still alive (headless probe) — if expired, it opens the browser and prompts for a fresh OTP automatically.

## Running the Tests

### 1. Login setup (run once, or when session expires)

```bash
node tests/e2e/Retail CRM/Chatbot/auth.setup.js
# or
npm run retail_crm:auth
```

What it does:
- Runs a **headless browser probe** to check if the saved session is still alive on the server
- If session is **still valid** → prints `session is alive` and exits immediately (no OTP needed)
- If session is **expired** (or no saved session) → opens a visible browser, enters `9000000001`, prompts you to enter the OTP in the terminal, completes login, and saves the new session to `.auth/retail_crm-auth.json`

> **Important**: The dev-server session expires in ~3–4 minutes.  
> Run the tests **immediately** after setup completes.

Force a fresh login (skips the probe, always requests a new OTP):
```bash
node tests/e2e/Retail CRM/Chatbot/auth.setup.js --force
# or
npm run retail_crm:auth:force
```

### 2. Run homepage UI tests

```bash
npm run retail_crm:homepage
# or
npx playwright test tests/e2e/Retail CRM/Chatbot/homepage.spec.js
```

### 3. Run OTP login page tests (no auth needed)

```bash
npx playwright test tests/e2e/Retail CRM/Chatbot/mobileNumber.spec.ts
```

### 4. Run all Retail CRM Chatbot tests

```bash
npx playwright test tests/e2e/Retail CRM/Chatbot
```

### Other useful commands

```bash
# Run a single test by ID
npx playwright test --grep "HP-14"
npx playwright test --grep "TC-12"

# Open HTML report after a run
npx playwright show-report
```

| Feature | Detail |

## Notes

- **TC-17 to TC-19** make live API calls to the dev backend. A valid but non-whitelisted number returns a `div.text-red-400` error banner — this is expected behaviour in the dev environment.
- **HP-18 / HP-19** make a real API call to the chatbot backend and wait up to 30 seconds for a bot response.
- The submit button is **disabled client-side** until exactly 10 digits are entered — there are no inline field-level error messages for partial input.
- Optional UI regions (sidebar, avatar, logo) **self-skip** if not found, so the test run never fails on layout variations between environments.
